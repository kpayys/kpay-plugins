# 常见问题

按下单时看到的报错文字查找。

## 下单报错

| 报错 | 原因和处理 |
|---|---|
| **签名验证失败** | 商户ID或 EPay Key 填错，或者 EPay Key 被重置过、旧的已经失效。注意 EPay Key 不是「平台 API」密钥的 Secret。复制时别带空格 |
| **用户不存在或已禁用** | 商户ID填错，或 KPay 账户被停用 |
| **回调地址校验失败** | 通知地址的域名不在 EPay 密钥的授权域名里。到 KPay「API 密钥」编辑这把密钥，把系统实际使用的域名加进去 |
| **授权域名归属验证未通过** | 授权域名还没通过验证。按页面提示放好 `kpay-domain-verification.txt` 或配置 DNS TXT，然后点验证 |
| **授权域名AI巡查未通过** | 验证通过后 KPay 会巡查站点内容，未通过或还在巡查中时不能下单。在「API 密钥」页查看结果和原因 |
| **当前请求IP不在白名单内** | EPay 密钥设了 IP 白名单：把服务器出口 IP 加进去；如果用的是浏览器表单提交方式，请求来自付款人的网络，改成服务端下单或者去掉 IP 白名单 |
| **EPay API Key 已停用** | 这把密钥被停用了，重新启用或换一把 |

## 付款成功，但订单没变成已支付

1. **看 KPay 有没有送出通知**：KPay 商户后台的订单详情里有通知记录和你的系统返回的内容。
2. **通知没送到**：你的站点要能被外网访问；CDN、WAF、宝塔防火墙、安全插件不要拦截通知地址（KPay 的通知是 GET 请求）。
3. **送到了但返回的不是 `success`**：多半是验签失败（密钥填错）或金额不符，各插件的日志 / 订单备注里有具体原因。
4. KPay 会对失败的通知自动重试；在「EPay 配置」开启 **自动补单** 后，漏掉的通知也会补发。

## 付款后没有跳回我的网站

跳转地址同样要在授权域名下。另外，是否入账以异步通知为准，跳转只是展示结果，没跳回不影响到账。

## 手机上打开的是电脑版付款页

大部分插件会把付款人的终端类型（`device`）传给 KPay。服务端下单又拿不到终端信息的系统（比如 SSPanel），保持「EPay 配置」的 **响应模式** 为默认的「收银台」，KPay 收银台会自动适配手机和电脑。

## 金额对不上

通知里的 `money` 是下单时的金额，插件只在它和订单金额一致时入账。开了附加服务费或优惠券时，付款人实际付的金额在 `payable_amount` 里，`money` 不变。

## 店铺不是人民币

KPay 只收人民币。WHMCS 用「Convert To For Processing」换算成 CNY；WooCommerce 需要把店铺货币设为人民币；其他系统请用人民币标价。

## 支持哪些付款方式

支付宝（`alipay`）、微信支付（`wxpay`）、云闪付（`unionpay`）。不传或传其他值时，付款人在 KPay 收银台里自己选。QQ 钱包、京东支付、USDT 不支持。

## 怎么退款

- 插件支持后台退款的（彩虹易支付、超级支付、WHMCS、WooCommerce、智简魔方）：配置「平台 API」密钥（勾选「发起退款」权限）后，在各系统的订单页退款。见 [KPay 准备](kpay-setup.md#可选退款用的-api-key)。
- 其他情况：在 KPay 商户后台对订单发起退款，再在你的系统里手动记录。

## EPay Key 丢了

EPay Key 只在创建时显示一次。到「API 密钥」页点 **重置 EPay Key** 生成新的，旧的立即失效，记得同步更新所有用到它的系统。
